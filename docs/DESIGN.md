## 0. 决策记录

本轮已确认的三个前提，后续设计全部以此为准：

| # | 决策 | 影响 |
|---|---|---|
| D1 | 定位 = **公开浏览 + 私密长信** | 需要一层"门"把私人内容隔开；公开层要经得起陌生人看 |
| D2 | 范围 = **全面重做视觉** | 配色、字体、构图、动效节奏全换；渲染内核复用（见 §9.3） |
| D3 | 成长维度 = **她的关键节点年鉴** | 内容模型的核心从"照片"转为"里程碑"；不做数据图表、不做粉丝共创 |

**明确不做**（写在这里是为了防止范围蔓延）：

- 不做后端、不做数据库、不做登录注册
- 不做**页面内**实时抓取（B 站接口没有 CORS 头，浏览器 fetch 必然失败）；改为构建时抓取，见 §7.4
- 不做逐日直播热力图（无公开接口，抓不到开播历史）
- 不做公开留言 / 投稿 / 审核
- 不做多语言、不做 PWA、不做后台管理

## 1. 一句话定义

> 一个以「凌晨两点的直播间」为场景的年度档案：每年她生日前后亮起一次，用她这一年的关键节点，记录一个 UP 主如何长成她自己。

区别在于——**它不是相册，是年鉴。** 相册看完就完了；年鉴会让人想明年再回来对一次。

---

## 2. 目标与非目标

### 2.1 目标

1. **她打开时，第一眼认出"这是我的站"**，而不是"一个粉丝做的生日页"
2. **陌生人打开时，五分钟内理解她是谁、这一年做了什么**
3. **你每年只需 30 分钟**就能完成一次更新，且不会漏步骤
4. 在 4G 网络 + 三年前的中端安卓上，首屏 3 秒内可交互

### 2.2 非目标

- 不做粉丝社区（没有 UGC，就没有审核成本）
- 不做数据看板（数字只作为里程碑的注脚，不画曲线）
- 不追求"炫技"（3D 地面网格在新版里降级为氛围，不再抢主体）

## 3. 受众与场景

| 角色 | 场景 | 诉求 | 设计对策 |
|---|---|---|---|
| **她本人** | 生日当天直播结束后，一个人点开 | 被认真对待的感觉；不想看到错的信息 | 内容精确、无错别字、私密段落有仪式感 |
| **她的粉丝** | 从动态/评论区点进来 | 快速知道她今年干了什么；找共鸣 | 年鉴前置、里程碑可扫读、弹幕可参与感 |
| **你自己** | 明年此刻，回来补一条 | 别让我记流程；别让我改代码 | 单文件内容模型 + 校验脚本 + SOP |
| **搜索引擎** | 不该来 | — | `noindex` + `robots.txt` 双保险（沿用 v1） |

> 关键取舍：**她 > 粉丝 > 你**。任何冲突时，优先保证她打开那一刻的体验。

## 4. 核心洞察

### 4.1 现状为什么不够

v1 的一年 = `messages` + `photos` + `quotes` + `letter`。四个字段全是**静态素材**，没有时间、没有因果、没有对比。结果是：

- 2025 和 2026 两个文件的内容几乎一模一样，因为"填什么"没有结构约束
- 页面能展示"这一年有哪些照片"，但不能回答"这一年她变成了什么样"
- 时光轴是**并列**的，不是**递进**的

### 4.2 v2 的支点：里程碑

她的成长本身就是现成的、可考的、有日期的：

- 2024-11 直播出现「老艺术家」「先天小红圣体」标签
- 《答应兄弟们的十万粉女装来了》—— 兑现承诺，是"十万粉"这个节点
- 《辣椒素你声音真是太好听了》—— 约 220 万播放，是"出圈"
- 2025-12「十二月对我好一点！」系列直播
- 粉丝量级 131.7 万（待核）—— 是结果，不是过程

这些条目一旦结构化，页面就自动有了**递进感**：翻过年鉴，你会看到一条从十万到百万的线。

> 设计原则：**用事件记录成长，不用形容词记录成长。**

## 5. 视觉概念

### 5.1 概念：「凌晨两点的直播间」

不要再是星空。星空是所有人的，直播间的暗场是她一个人的。

画面构成（三层，自下而上）：

1. **暗场**——近黑的暖灰底，带极轻的红色噪点与横向扫描感（模拟夜里摄像头的画面），非常克制，不能看出"特效"
2. **舞台灯**——一束从上方斜切的暖光，边缘柔和，只照亮画面主体所在区域；其余部分沉下去
3. **主体**——粒子构成的文字 / 头像，颜色取辣椒红与暖白

高潮时刻（生日当天演出结束）允许一次"直播礼物特效"式的爆发：从画面底部升起红色光点，与粒子文字同频，**不使用任何 B 站真实 UI 元素或礼物图标**。

### 5.2 为什么是这套

| 元素 | 来自她身上的什么 |
|---|---|
| 辣椒红 | 名字本身。「辣椒素」是这个站唯一不需要解释的符号 |
| 深夜暗场 | 她的主战场是直播间（`31259021`），不是风景、不是城市 |
| 暖白而非纯白 | 直播补光灯的颜色。冷白会让整个站显得像科技产品 |
| 横向扫描 / 噪点 | 摄像头质感，让"公开浏览"的部分有一层"你在看她的画面"的距离感 |
| 硬朗黑体 | 东北、直率、"老艺术家"。不是软妹体 |
| 宋体只出现在信里 | 私密段落换字体，是最省力也最有效的反差 |

### 5.3 设计令牌

```css
/* 底色：暖黑，不是纯黑
   2026-11-12 整体抬高一级 —— 原来的 #0B0909 在大屏上是一片死黑，
   全屏亮度只有 4%~9%，中间没有任何层次。见 §16。 */
--ink-900: #1A1211;   /* 页面底 */
--ink-800: #2A1C19;   /* 卡片底 */
--ink-700: #3B2924;   /* 分隔 / 描边 */

/* 主色：辣椒红 */
--red-600: #C42B20;   /* 按下 / 描边 */
--red-500: #E23A2E;   /* 主色 */
--red-400: #FF5546;   /* 高亮 / 数字 */

/* 辅色：舞台灯 */
--amber-400: #FFA53D; /* 光斑 / 强调 */
--amber-200: #FFD9A8; /* 渐变中段 */

/* 文字 */
--cream-50:  #FFF4E6; /* 主文字（暖白，不用 #FFF） */
--cream-300: #C9B8AE; /* 次级文字 */
--mute:      #7A6B66; /* 说明 / 日期 */

/* 粒子渐变（头像 / 昵称专用） */
--grad-top:  #FFE2A0;
--grad-mid:  #FF6B5A;
--grad-bot:  #FF3B2E;
```

**规则**：全站不允许出现纯 `#FFFFFF` 与纯 `#000000`。暖白和暖黑是这套视觉的底色信任。

### 5.4 字体

| 用途 | 字体 | 说明 |
|---|---|---|
| 大标题 / 年份数字 | Noto Sans SC **Black** + `font-variant-numeric: tabular-nums` | 数字要等宽，倒数不能跳动 |
| 正文 / 里程碑标题 | Noto Sans SC Regular / Medium | 系统字体兜底 |
| 私密长信 | Noto Serif SC Regular | 全站唯一的衬线，制造"这是信不是页面"的切换 |
| 英文 / 日期 | JetBrains Mono / ui-monospace | 日期、BV 号、粉丝数用它，像档案编号 |

字号阶梯（移动优先，`clamp` 实现）：`12 / 14 / 16 / 20 / 28 / 40 / 64 / 120`。

### 5.5 版式

- **倒数页**：数字是唯一主角。`clamp(96px, 22vw, 200px)`，居中，辣椒红发光，背后一团红色余晖，底部一行说明。**粒子层在倒数页直接关闭**（原本计划降到 15%，实测在那个尺度上只剩一块读不出形状的马赛克，比关掉更脏）
- **年鉴**：横向 `scroll-snap` 频道，一年一屏，像直播回放列表横向滑动。桌面端可用滚轮横向驱动
- **信件**：整屏遮罩 + 纸感底（暖白 8% 叠加），宋体，行高 1.9

### 5.6 落地时的偏差（按实际实现记录）

纸面上的方案有三处落不了地，实现时改了，理由记在这里，免得以后照着文档改回去：

| 原方案 | 实际做法 | 为什么 |
|---|---|---|
| 舞台灯做成独立图层（`clip-path` 梯形 + 模糊） | 放进 `body` 背景，改成偏右上的一束椭圆光斑 | `filter` 先于 `clip-path` 生效，模糊会被裁掉，边缘硬得像一块灰色色板。光应该是"打上来"的，不是"画上去"的 |
| 颗粒与扫描线做独立全屏叠加层（`mix-blend-mode: soft-light`） | 并进 `body` 的多层背景 | 独立叠加层 + 混合模式每帧都要重新合成，实测掉 10fps（40 → 53）。并进背景后开销为零 |
| 倒数页粒子层降到 15% 亮度 | 直接关掉（`opacity: 0`），改用一团 CSS 红色余晖 | 在倒数页的尺度上，爱心只剩一块深色马赛克，形状读不出来 —— 比关掉更像脏斑 |
| 烟花"换调色"：给 `#canvas` 加 CSS 滤镜 | 加载时把 10 张贴图烘一遍（`ctx.filter` + 离屏 canvas），画布本身不加滤镜 | 上一版记的「实测无掉帧」是错的 —— 在烟花最密的那几秒复测，61fps 掉到 23~29。给运动中的全屏画布加颜色矩阵，等于每帧重算一次全屏。烘到像素上之后回到 55fps |

另外两个实现层面的固定手法：

- **按钮不用 emoji。** 用 `<i class="fab-ico">` 放等宽字形（`♪ ≋ ▤ ⊙ ♡`）。带颜色的 emoji 一出现，整站立刻变成"礼物模板"。
- **中文不用大字距。** `letter-spacing: .34em` 在西文是广播感，在中文会把词拆成一粒一粒。中文标题压到 `.02em`，只在等宽小标签上用 `.16em`。

### 5.7 中文粒子文字：四个数决定字认不认得出

这套引擎原版是给英文单词写的 —— 字母笔画少、留白多，粒子稀一点更像点阵。换成汉字之后，
笔画细密，默认参数下整块字会烧成一条**白色灯管**，配色只在边缘露一圈。

| 参数 | 原值 | 现值 | 作用 |
|---|---|---|---|
| 采样间距 `gap` | 13 | 6（桌面）/ 5（手机）<br>（2026-11-12 再从 9/6 收紧一档，见 §20.3） | 决定笔画密度。13 时一个四字祝福只剩两百来颗粒子，笔画立不住 |
| 光晕直径系数 | 6.4 | 2.8 / 2.2 | 乘粒子半径，再**硬压在网格的 1.45 倍以内** |
| 光晕峰值透明度 | 1.0（核心固定近纯白） | 0.62（核心取本色提亮 22%） | 原值让每颗粒子的芯都是白的，几百颗一叠必白 |
| 两侧留白 `fitW` | 0.8 | 0.8（桌面）/ 0.92（手机） | 手机上五个字要塞进 390px，留白太多等于把字压小 |

**踩过的坑，按顺序记：**

1. 只改核心颜色 → 有颜色了，但笔画被大光晕吞掉，字糊成一团
2. 光晕收到 4.2 → 字散成一片点，形状读不出来
3. 间距从 13 收到 9 → **又过曝成白**。因为 `lighter` 是加法混合，密度翻倍等于亮度翻倍
4. 峰值压到 0.62、光晕 4.0 → 当时判断"能读出「一百万人」"
5. 峰值又调回 0.75 → **这个改动是错的，且当时没发现**。2026-11-11 用 1440×900 逐帧截图复核，
   「祝」「一百万人」「生日快乐」全部糊成橙色云，只有「辣椒素素素」（五字、字号最小）勉强能认。
   字号越大笔画越粗，光晕叠得越狠 —— 所以**越短的句子越糊**，这跟直觉相反
6. 峰值回 0.62 + 光晕 4.0→2.8 + 光斑上限 1.45×gap → 四句全部可读，「生日快乐」点阵清晰

> 记住两条：
> 1. **在这套引擎里，密度和亮度是同一个变量。** 想加密就必须同时压暗，只加密会白，只压暗会散。
> 2. **光斑直径是相对网格定义的，不是绝对像素。** 手机网格收到 6 之后，同一套粒子半径意味着
>    光斑相对字宽放大了一半 —— 不设 `Math.min(..., GRID_GAP * 1.45)` 这道上限，手机必糊。

**手机端的极限**：390px 宽、五个字，每字 70px 上下，`gap` 6 也只有十二三行粒子。
汉字横画的间距比网格还窄，笔画必然粘连。**手机上读到的是节奏与轮廓，不是字。**
真正的落点是头像帧 —— 所以手机端不值得继续为字号调参。

**另修掉的一个隐性 bug**：新粒子原来出生在画面正中（`new S.Dot(a.w/2, a.h/2)`），
一整批叠在同一个点、透明度还是满的，加法混合下先在字中间烧出一个白球再飞散。
每一帧都如此，观感像字被打了洞。改为出生点随机撒在画布任意处、透明度从 0 起。

### 5.8 头像帧：采样方式决定"像不像她"

头像是深蓝底 + 奶油色猫脸的平涂图（`images/avatar.png`，240×240）。

| 采样方式 | 结果 |
|---|---|
| `light` 取亮部 | 只剩猫脸那一整块，眼睛、鼻子、嘴全在暗部被筛掉 —— 聚出一个**没有五官的圆团** |
| `alpha` | 需要抠好的透明 PNG，手上这张没有 |
| `edge` 取轮廓 | 只放"明暗突变"的格子 → 外轮廓、耳朵、眼睛、嘴都留得住，**像一幅星座线稿**（当前用这个） |

`edge` 的实现要点：`getImageData` 拿到的是**整张图**的像素，所以采样器可以在一个 `gap × gap`
的方块里逐像素找边界，而不是只看采样点自己 —— 只看一个点的话，细过网格的线条会有一大半漏掉，
聚出来是断断续续的虚线。阈值 22 是"线够全、但脸不会变成实心块"的位置。

| 幕 | 时长 | 画面 | 情绪 | 交互 |

| **四 · 这封信** | 38s+ | 口令门 → 纸感整屏 → 打字机 | 私密 | 输入口令；可跳过打字 |
| **五 · 年鉴** | 常驻 | 横向年份频道，每年：里程碑 + 照片 + 她的话 | 回望 | 左右切换年份；点里程碑可跳 B 站原视频 |

**节奏表**（毫秒，落地时写入 `config.js`）：

| 环节 | 时长 | 可配置项 |
|---|---|---|
| 暗场入场 | 800 | `introFade` |
| 每条祝福语停留 | 2000（大屏）/ 2600（小屏） | `msgHold` |
| 祝福语条数 | 8–12 条 | 内容决定 |
| 头像停留 | 5000 ×2 | `portraitHold` |
| 中间昵称 | 2000 | `accentHold` |
| 头像入场特效 | 1200 | `portraitEnter` |
| 弹幕出现 | 6000 起，循环 | `danmakuDelay` |
| 头像前弹幕淡出 | 提前 2000 | `danmakuFadeLead` |
| 长信浮出 | 序列结束后 2500 | `letterDelay` |

>
> 实测（`node tools/timing.mjs <年份> [mobile]`）：
>
> | 版本 | 桌面 1280×800 | 手机 390×844 |
> |---|---|---|
> | v1（祝福语 10 条，头像 7000/2600） | 41.8s | 49.4s |
> | v2（祝福语 5 条，头像 5000/2000） | 26.2s | 32.0s |
>
> 上一版文档写的「接近 60 秒」是估算，比实测高。真实结论是：**v1 只有手机超了 45 秒**，
> 桌面一直在范围内。压缩幅度没有原先估计的那么大。

## 7. 内容模型 v2

### 7.1 结构

```
/data
  years.js          ← 年份清单（唯一需要手改的地方）
  history.js        ← 粉丝采样点 + 四段台阶
  me.js             ← 「我」的关系线（只有本人能写）
  fandom.js         ← 「大家」留下的：录播留档 / 切片 / 二创
  2024.js
  2025.js
  2026.js
  2027.js
```

`years.js` 替代"在 index.html 里加 script 标签"——这是 v1 最容易忘、且忘了不报错的一步。

```js
// data/years.js
window.HB_YEARS = [2025, 2026];
```

### 7.2 单年文件 schema

```js
HB.year(2026, {

  // ---- 年鉴主体：这一年的关键节点（新增，核心）----
  milestones: [
    {
      date: '2026-01-17',                 // YYYY-MM-DD 或 YYYY-MM
      title: '把头发梳成大人模样',
      type: 'work',                       // work | live | milestone | meme | birthday
      note: '单条 157 万播放',             // 一句注脚，可空
      link: 'https://www.bilibili.com/video/BV1hKrSBoE4B',  // 可空
      cover: 'images/2026/m01.jpg',       // 可空，缺省用渐变卡
    },
  ],

  // ---- 这一年的坐标（自动抓取，不需要手填）----
  // 来源：data/bili.json（tools/fetch-bili.mjs 生成）
```

### 7.4 数据来源与抓取边界（实测结论 · 2026-11-11）

抓取由 `tools/fetch-bili.mjs` 在**构建时**完成，产物是 `data/bili.json`，页面只读这个静态文件。这样接口挂了站也不会挂，只是数字停在最后一次成功的日期（`stale: true`）。

| 数据 | 接口 | 实测 | 用法 |
|---|---|---|---|
| 粉丝 / 关注数 | `x/relation/stat` | ✅ 稳定 | 每次抓取 |
| 昵称 / 签名 / 头像 / 等级 / 铭牌 | `x/web-interface/card` | ✅ 稳定 | 每次抓取 |
| 直播间标题 / 分区 / 热词 | `live.../Room/get_info` | ✅ 稳定 | 每次抓取 |
| 投稿数 / 相册数 / 动态数 | `x/space/navnum` | ✅ 稳定 | 每次抓取 |
| 投稿视频列表 | `x/space/wbi/arc/search` | ⚠️ 需 wbi 签名，**实测触发 -412 IP 封禁** | 仅 `--videos` 手动运行，**不进定时任务** |
| 直播开播历史 | 无公开接口 | ❌ 需登录态 | 放弃；改用「陪伴天数」 |

三条约束写在这里，防止以后有人想当然：

1. **不允许前端 fetch**。这些接口不返回 `Access-Control-Allow-Origin`，写进页面的请求会被 CORS 直接拦掉。
2. **不允许高频抓取**。实测连续探测就会吃到 `-412 request was banned`，恢复时间不可控。每日最多一次，且必须带 800ms 间隔。
3. **数字必须有出处**。页面上所有来自接口的数字都要带「数据截至 YYYY-MM-DD」，因为它是快照，不是实时值。

### 7.5 两条时间线

从"开始直播"记录，意味着这个站有两条并列的主线：

| 时间线 | 起点 | 含义 |
|---|---|---|
| **生日线** | 每年 10-20 | 长大一岁 |
| **开播线** | 2024-07-17 19:00 | 成为 UP 主 / 和大家见面 |

开播二周年 = 2026-07-17。页面上的「陪伴天数」由 `broadcastStart` 实时计算，不需要抓取，也不会错。

> 这两条线交叉，才是"成长"。只有生日线，那只是年龄。

## 9. 技术方案

### 9.1 不变的部分

- 纯静态、无构建、无依赖
- `file://` 下不可用的约束保留，用 `python -m http.server` 预览
- Cloudflare Pages 部署 + `_headers` 缓存策略（入口与 data 不缓存）
- `noindex` + `robots.txt`

### 9.2 私密长信的实现与边界（重要）

公开站 + 私密内容的组合，只有两个选项：

| 方案 | 安全性 | 成本 |
|---|---|---|
| 纯前端口令（SHA-256 比对） | **只能防"无意点开"，防不住任何人** | 0 |
| Cloudflare Access / 后端鉴权 | 真正安全 | 需要配置、需要她登录 |

**建议采用纯前端口令**，并在文档与代码注释里明确写出它的安全边界。理由：这里要保护的是"不想被陌生人随手看到的心事"，不是机密数据；她本人拿到的是直接链接。

实现要点：
- 口令不明文写在仓库里，存 SHA-256；提供 `tools/hash.mjs` 生成
- 口令输入 3 次失败 → 冷却 30 秒，仅防误触
- 解锁状态存 `sessionStorage`，关标签页失效
- 图片若涉隐私，放在 `private/` 目录并在 `_headers` 里加 `X-Robots-Tag: noindex`

## 15. 私密长信与三连（2026-11-12 补记）

三封信写完之后，信纸和三连是第一次真正被人看见 —— 之前 `letter` 是空数组，
`Letter.show()` 从来没被调用过，下面这些问题全藏在「没打开过」里。

### 15.1 信件：四个坑，按踩到的顺序

| 现象 | 原因 | 处理 |
|---|---|---|
| 写好的段落全粘成一片 | `letter.js` 的 `toLines` 和 `check-data.mjs` **各 filter 了一次空行**，分段被吃了两遍 | 两边都不再过滤，只切首尾；空行渲染成 `.letter-gap` |
| 段落间距比行距还小 | `.letter-gap` 高 15px，小于一行文字的 33px —— 等于「空行比有字的行还矮」 | 行 margin 6px、gap 18px：行间隙 ≈ 22px，段间隙 ≈ 46px |
| 最后一行被按钮压成半截 | flex 子项默认 `min-height: auto`，`.letter-body` 拒绝收缩，内容溢出到 `.letter-actions` 下面 | `.letter-body { flex: 1 1 auto; min-height: 0 }` |
| 信一打开，61fps → 24fps | `#letter` 的 `backdrop-filter: blur(6px)` 覆盖全屏，底下是每帧都在变的粒子/烟花 | 去掉模糊，遮罩加深到 `.955`。跟 §6 那条「运动 canvas 上加 blur 是灾难」是同一个坑 |

另外三处修正：

- **信纸 560 → 620px。** 中文每字约等于字号宽，560 的箱子一行只放 27 字，而信里最长一句 30 字 ——
  会折成「最后两个字掉到下一行」，一句一行的手写感就断了。现在一行 31 字，三封全部不折行。
- **「跳过」回顶部，不是底部。** 按跳过的人是想把全文看一遍，停在最后一行等于让他自己往上翻。
- **`z-index` 9600 → 9760。** 必须压过 `#toast`(9700)，否则手机上「点击右上角的按钮可以开启音乐」
  那条提示正好落在正文上。信打开时还会主动收掉 toast —— 它是全屏唯一的白字层，会从半透明信纸底下透出来。

打字速度 `70ms/字 → 58ms/字`：一封 260 字的信原本要打 31 秒，加上前面 26 秒演出接近一分钟，太拖；
现在约 23 秒。跳过按钮始终在。

### 15.2 三连：三个问题，根子在同一处

原话是「三个点击完后动画有点丑，还有跳出来的东西也奇怪，还有不能一键三连」。

| 问题 | 原来是什么 | 现在 |
|---|---|---|
| 丑 | 完成时整组按钮 pop 到 1.28 倍，同时 24 个**彩色 emoji**（👍🪙⭐🎉💖）从屏幕顶部落下 | 一圈柔光从按钮位置向外爆开 + 15~18 个衬线字符（♥ ✦ · ✧）从按钮**向上**飘 |
| 奇怪 | 图标是系统 emoji，在这套深色红金 + 衬线的画面里就是贴纸；「天上下雨」跟「我按了三下」没有因果关系 | 图标换成内联 SVG 描边（feather 路径，1.6px）；点亮只让图标闪一下，不动按钮 |
| 不能一键 | 没有这个按钮，必须点三次 | 加「一键三连」主按钮，三个依次亮起，间隔 130ms |

入场同样修了：原来 `display: none → flex` 是瞬间蹦出，现在 `visibility + opacity + translateY(14px)` 过渡 0.6s。

**还有一个只在窄屏出现的布局 bug**：`#triple` 原来用 `left: 50%` + `translateX(-50%)`，
fixed 元素在 `left: 50%` 之后 shrink-to-fit 的可用宽度只剩半屏（256px），四个按钮挤在里面，
文字被迫竖排成「点 / 赞」。改成 `left: 0; right: 0; justify-content: center`。

出场时机也改了：原来在信**打字完成**时就 mount，那时信还盖着画面，而三连 `z-index`(9400)
低于信纸(9600)，只会在信下面露一角。现在等信收起（onClose）之后再放出来。

### 15.3 校验规则加了两条

`tools/check-data.mjs` 现在会检查：

- 单行超过 32 字 → 提示会折行
- 有 4 行以上但**没有任何分段** → 提示缺 `''` 空行元素

后者是因为踩过一个更隐蔽的坑：**JS 数组里的裸空行不是元素，只是格式空白。**
`['a',` 换行 `'b']` 的长度是 2。想要分段必须显式写 `''`，否则数组里根本没有那一段。


## 16. 色温抬高 + 换曲（2026-11-12 深夜）

### 16.1 问题不是"黑"，是"没有中间调"

原话是「整体颜色太黑了，不好看」。查了一遍才发现真正的毛病：
全屏亮度都挤在 **4%~9%** 这一段，`#070505` 到 `#171112` 之间没有别的值。
一条只有 4% 振幅的曲线，看在眼里就是"一块黑布"，不是"一个暗房间"。

所以只加"更亮"没用，要**拉开明暗差**：

| 位置 | 改前 | 改后 |
|---|---|---|
| 页面底 `--ink-900` | `#0B0909` | `#1A1211` |
| 卡片底 `--ink-800` | `#141011` | `#2A1C19` |
| 分隔描边 `--ink-700` | `#1F191A` | `#3B2924` |
| 基底渐变 | `#171112 → #0B0909 → #070505` | `#261A17 → #1B1412 → #110C0B` |

### 16.2 光要有形状，或者要对称

中间试过一版"右上打一盏灯"。截图一看就是**一块污渍**——因为没有形状，
低透明度的椭圆光斑偏在一角，读者不会理解成灯，只会理解成脏。

**结论：没有形状的光，只有对称才立得住。** 最终是居中顶光：

```
颗粒 → 扫描线 → 顶光(50% -14%) → 左侧光 → 右侧光（藕紫，做冷面对手）
     → 底部红（像灯打在木地板上） → 内容光池 → 基底
```

侧光那两盏负责把画面横向撑开，右上那抹藕紫是给红金一个冷面对手 ——
全是暖色会糊成一片橙，需要一个冷调把纵深拉开。

### 16.3 换曲

`happy-birthday.mp3` 是通用生日曲，和"辣椒素素素"没有关系；换成张芸京《偏爱》
（v1 用的就是这首）。两处工程问题：

- **中文文件名 + 空格**：GitHub Pages 对路径编码挑剔，重命名为 `bgm-pianai.mp3`
- **10.2MB / 386kbps**：原文件还内嵌了一张封面 PNG。`ffmpeg -b:a 160k -vn` 重新编码，
  降到 **4.26MB**，时长不变（212.95s），浏览器 `readyState=4`、无解码错误

### 16.4 一个走错的方向，记下来

试过 AI 生成焦外光斑铺底。做了三件事想让它能用：
裁掉右下角平台水印、`colorlevels` 压掉底色只留光点、`background-blend-mode: screen` 只加光。

**最后没用。** 在这个亮度下光斑根本看不见；想让它可见就得提亮，
一提亮又变成"褐色雾"，比纯黑更糟。已删除，没有留在仓库里。

顺带验了一个怀疑：加 `background-blend-mode` 会不会掉帧。同条件对照
（改前 42~48fps / 改后 42~45fps）**没有差异** —— 之前看到的 61fps 是机器空闲时的读数，
不是基线。**测帧率必须在同一台机器的同一状态下对照测，不能跨时间比数字。**

### 16.5 开关的状态语言（音乐 / 弹幕统一）

两个开关按钮（`#btn-mute`、`#btn-danmaku`）表达"关"的方式必须完全一致，否则
会出现"弹幕按了看得出关了、音乐按了像没反应"的错觉。规则：

| 状态 | 文字 | 类 | 视觉 |
|---|---|---|---|
| 开 | 音乐开 / 弹幕开 | `fab` | 正常亮度，悬停变红 |
| 关 | 音乐关 / 弹幕关 | `fab fab--off` | `opacity: .52`，悬停回到 `.84` 但仍不泛红 |

- **淡化要过渡**：`.fab` 的 `transition` 里带 `opacity .3s ease`，按下是"暗下去"
  而不是硬跳。原来的 `opacity` 不在过渡列表里，弹幕按钮一直是啪一下变暗。
- **不要用 `grayscale`**：这两个按钮静止时本来就是米白（`rgba(255,244,230,.76)`），
  去色几乎看不出来，却会让同元素上的 `backdrop-filter` 在部分浏览器上失效。
  真正传达"关"的是亮度差。
- **图标不要靠 JS 换 emoji**：旧代码 `btn.firstChild.nodeValue = '🔇 '` 是无效写法
  —— `firstChild` 是 `<i class="fab-ico">` 元素，给元素赋 `nodeValue` 不产生任何效果。
  图标固定用等宽字形 `♪` / `≋`，状态只由文字 + 压暗表达。已删掉这两行死代码。

验证方式（无头）：`syncMuteButton(true)` 后应得 `fab fab--off / 音乐关`；
点 `#btn-danmaku` 一次应得 `fab fab--off / 弹幕关`，再点回 `fab / 弹幕开`。

> `tools/shot.mjs` 加了 `--evalDelay`：本机 `Page.loadEventFired` 有时早于真实导航完成，
> `--eval` 会落在 `about:blank` 上（表现为 `getElementById` 拿到 null，或截图全白）。
> 传 `--evalDelay=1500` 即可绕开；`--eval` 的返回值现在也会打印出来，方便判断上下文。

## 17. 三连改长按 + 背景加城市（2026-11-12 白天）

### 17.1 三连不是"按钮"，是一个手势

原来的做法是三个按钮 + 一个高饱和的「一键三连」主按钮。问题不在动画，在于
**交互原型是错的**：B 站没有这个按钮，三连是"长按点赞"这个手势。

多一个主按钮的代价：画面里最抢眼的东西变成了一个渐变胶囊，而"三连"本该是
一个顺手的小动作。删掉之后三个按钮回到同一层级，才像 B 站的界面。

规则：

| 操作 | 结果 |
|---|---|
| 长按「点赞」900ms | 三连：三个依次点亮（110ms 间隔）+ 光环 + 上飘符号 |
| 轻点「点赞」（<260ms） | 只点亮点赞 |
| 单点「投币」「收藏」 | 只点亮那个；三个都亮同样算连成 |

实现要点：

- **进度值用 `@property --hold` 注册成 `<number>`**，才能对它写 `transition`。
  按住时 `--hold 0s`（跟手），松手时 `.3s`（弹回去）。
- **进度画在底色里**：`linear-gradient(90deg, 红 0, 红 calc(var(--hold)*100% - 26%), 透明 calc(var(--hold)*100%))`。
  前沿留 26% 宽的渐隐，否则半红半暗的分界线会把药丸劈成两个色块。
- **`setPointerCapture`**：手指按住后滑出按钮不丢，松手一定收得到。合成事件里
  没有活动指针会抛 `NotFoundError`，包了 `try/catch`。
- **`touch-action: none` + `user-select: none` + `-webkit-touch-callout: none`**：
  不然手机上长按会弹系统的"拷贝/查询"菜单。
- **满格先停 140ms 再撤 `--holding`**：立刻撤掉的话进度瞬间退回，"填满"这个
  结果根本没被人看见，只剩三个按钮突然变红。
- 确认文案「长按「点赞」一键三连」是必需的 —— 藏起来的手势等于不存在。

走过两个弯路，记下来：

1. **整块底色填红**（`background-image` 半红半透）→ 硬分界，像按钮坏了。
2. **底部 2px 进度线** → 在 40px 高的按钮上细到看不见，等于没有。

### 17.2 背景的问题不是"暗"，是"没有景"

前一轮只调了渐变参数（色温、光斑位置），用户反馈"没什么改动"——**这是对的**。
纯渐变的暗场，无论怎么调都只是一张没画完的模板：画面里没有任何具体的东西。

现在加的是「窗外的城市」：

- `images/skyline.svg` — 楼剪影，纯色 `#0E0A09`，只比基底暗一点。**不要纯黑**，
  纯黑的楼会变成一个个洞。楼之间留 6~26px 的缝，缝里透出底部红光。
- `images/citylights.svg` — 窗户灯点，单独一层（`#city`），只让这一层做 11s 的
  明灭。画进同一张图里会连楼一起亮，像屏幕亮度在变。
- 楼上方叠一层暖雾（`rgba(255,150,100,.11)` → 透明 22%），那是城市光污染。
  没有它，楼是"贴"在画面底部的黑纸片。
- 两张图都由 `python tools/gen-city.py` 生成，固定 seed，改风格重跑即可。

比例：楼只占底部 **24vh**。手机竖屏同一套图 `repeat-x` 缩放，楼会显得近一些，
这是对的（近大远小）。

### 17.3 烟花：先删掉两样东西

- **地面的橙色方格**。那是 cantelope.org 跨年夜广场的地砖，一个 3D 透视的
  亮橙色网格铺了半屏，每帧还要 rasterize 一两千个点。烟花在天上，地上不该有格子。
- **相机绕圈**。原来是 `playerX/playerZ` 绕中心缓缓转，整片画面一直在横移，
  看久了晕，而且粒子文字背后的东西老是漂。改成原地呼吸（±1.1，`yaw` 抖 0.018）。

另外两处：

- **一朵花一个主色**。原来每个 spark 各自随机取十张彩虹色，炸开是一把彩色沙子；
  真礼花一朵一色，留 14% 白芯做层次。拖尾那十个 case 的彩虹 `strokeStyle` 一并删了。
- **节奏 0.4 秒/朵 → 4~7 秒/朵**。密集连续的爆炸是屏保，不是礼花。稀疏下来之后
  每朵都能被看完、落净。

去网格 + 不绕圈之后同机帧率 43 → 61（1440x900，演出中）。

### 17.4 还差的

- 城市只在桌面看过，手机竖屏楼偏大（`repeat-x` 按高度缩放导致），需要单独一版
  更矮的天际线。
- 画面中部（文字与城市之间）仍偏空，可能需要一层极淡的地面反光。

## 18. 两套光线：安静期 / 生辰期（2026-11-12）

### 18.1 为什么不是"两个页面"

上一版的问题是：倒数页和生日演出页共用同一套光，只是把粒子层关了。
结果两边都不对 —— 平时那个 200px 的辣椒红数字在喊，生日那天也没比平时更热闹。

**生日要有待遇，平常要能安静。** 但如果做成两套页面，就有了两份要维护的样式，
改一个色调要改两处，早晚会走样。

所以做成一套结构、两套光：

```
:root                  → 安静期（默认，一年三百多天）
body.mode--festive     → 生辰期（生日当天起 celebrateDays 天内）
```

只切 CSS 变量，DOM 一个都不动。楼还是那些楼，窗还是那扇窗，
区别只是"今晚开了几盏灯"。

### 18.2 令牌清单

| 令牌 | 安静期 | 生辰期 |
|---|---|---|
| `--mood-top-a/b` | 窗外天光，很薄 | 舞台顶光，打下来 |
| `--mood-side-l` | **夜蓝**（窗外） | 暖橙（屋里） |
| `--mood-side-r` | 暗紫 | 暖金 |
| `--mood-bottom` | 红 .12（余温快灭了） | 红 .48（全开） |
| `--mood-haze` | .055 | .17 |
| `--mood-base-a/b/c` | 冷中性 | 回暖 |
| `--mood-city` | .46 | .92 |
| `--mood-accent` | 暖白 | 辣椒红 |

安静期最关键的改动不是"更暗"，是**侧光从暖红换成夜蓝**。
冷暖一分开，同一栋楼立刻从"直播间"变成"深夜的窗外"。

### 18.3 数字：从"喊"到"读"

原来倒数数字是 `200px / 800 字重 / 三层红光`——那是生日蜡烛的语言。
一年三百五十天都点着，生日那天就没灯可开了。

现在是 `122px / 300 字重 / 暖白 / 一层薄光`。
它是**读**的，不是**喊**的。

底下加了一条 `#cd-meter` 一年进度线（1px，`--year-progress`）。
数字告诉你"还剩几天"，线告诉你"走到哪里了"——前者是读数，后者才是等待的手感。
生日过完那天它会回到 0，新的一年重新开始。

### 18.4 生日那天的金

`SITE.theme.paletteFestive`：平时粒子是辣椒红，生辰期换成烛光金
（`[255,214,126]` 权重最高，`[255,238,196]` 做高光，末尾留一格红做点缀）。

一年里只有这几天，她的名字是金色的。全金会变成红包封面，所以红必须留着。

烟花节奏也跟着放开：安静期 4~7 秒一朵，生辰期 2~4 秒一朵。

### 18.5 两个坑

**① `background-size` / `-repeat` / `-position` 的数量必须等于 `background-image` 的层数。**

少一项不报错 —— 浏览器会让最后一层循环取第一个值。这次 `body` 有 10 层背景，
size 只写了 9 项，于是**基底渐变被压成 140px 的方块并平铺**，整屏浮出一层方格。

排查方式（不要用眼睛数层）：

```js
getComputedStyle(document.body).backgroundSize
// 数逗号。末尾如果出现 "140px 140px" 而不是 "auto"，就是错位了。
```

**② 不要缓存"现在是哪种氛围"。**

烟花的第一帧可能早于 `mode--festive` 挂到 body 上，缓存在变量里会永远停在
安静分支。这段几秒才跑一次，每次重读 `classList.contains` 就行。

### 18.6 怎么预览

| 地址 | 看到什么 |
|---|---|
| `/` | 按今天真实日期自动判断 |
| `/?celebrate&auto` | 强制生辰期 + 跳过引导层直接开演 |
| `/?celebrate&quiet` | 强制安静期（生日当天想对照两版时用） |

## 19. 开场：三年的光（2026-11-12 夜）

### 19.1 为什么删掉"一上来就是生日快乐"

原来的演出是：点开播 → 倒数 3、2、1 → 粒子聚成「祝」「辣椒素素素」
「生日快乐」「一百万人」「好幸福」→ 头像 → 心。

这套东西本身没做错，问题是**它的语法是贺卡的**：给你一句话，配一堆特效。
第一年是惊喜，第二年是熟悉，第三年就是一张旧截图。用户的原话是
"和之前一样，感觉一般般"——这个判断是准的，因为它每年只能换文案。

真正的问题：**这场演出没有主语，也没有过程。** 画面里只有特效，没有"她"。

### 19.2 换成什么：让光按真实的增长曲线长出来

这一站手里有一件别处没有的东西：**她真实的三年**。
`data/history.js` 里有 11 个带日期的采样点，从 2024-04 的 1000 人到
现在的 1,386,504 人。这些数字一直只被用来画一个从没渲染过的板块。

现在它们驱动画面：

```
0.0s   一片暖色的夜，中央一颗光点在呼吸          ← 一个人
2.6s   光点从城市底部升起，落在天上              ← 有人来了
  ~22s  按真实日期走完三年，光点从 1 颗长到 980 颗
24.0s  所有光向中心收拢
28.2s  收成一个有浓有淡的星云核心
30.0s  淡出，把画面交给粒子字
```

光点全部从**画面下沿**升起 —— 那是城市的位置。"从地上长出来"和
"天上本来就有"是两种完全不同的意思。

配合的一句字幕随采样点走：`2025-08 · 50 万人` →
最后收拢时换成「一百三十八万人，今晚都在」。

**这句话里的数字是从数据算的，不是写死的。** 明年涨到两百万，
它自己会变成"两百万"（`cnWan()`，见 js/opening.js）。

### 19.3 三个决定性的参数

**① 时间轴按真实日期，不按采样点均匀分配。**

采样点不是等距的：2024-04 到 2025-01 有 9 个月，2025-12-11 到 2025-12-21
只有 10 天。均匀分配意味着"1000 → 14 万的那 9 个月"和"60 万 → 64 万的
10 天"占一样长的时间。

按真实日期走之后，前 7 秒几乎是空的。**这个"空"是内容的一部分**——
她熬了九个月才等到十四万人。等得久，才看得见"熬"。

**② 数量映射用 0.42 次方，不是 0.5。**

1000 比 1,386,504 差 1386 倍。线性轴会把前两年压成一条贴地的线。

开方（0.5）是常见的折中，但 14 万人在开方后已经占掉三分之一的屏幕，
后面两年全挤在剩下的三分之二里。0.42 下 14 万人只占 341/980，
后面还留着长大的余地。

**③ 结尾是收拢，不是上浮。**

第一版让光点在最后四秒缓缓往上飘，结果是一屏光点飘出画面 ——
没有落点，整段演出等于没有结尾。

改成收拢之后才有"攒起来"的意思：三年的光最后攒成一个核。
`pull = pow(lift, 1.5) * 0.03`，前半段几乎不动，最后一秒才明显加速。
匀速收拢看起来像"镜头推远"，加速收拢才像"攒"。

落点不是同一个像素，是各自散在中心附近一个盘上（`oa` / `or`）。
980 颗全叠在一个点上，`lighter` 会把它烧成一块边缘一刀切的死白圆片，
像贴纸；摊开之后核心才有羽化，才像星云。

### 19.4 亮度：抬中间调，不是加白

用户连着两次说"太暗"。第一次我以为是氛围问题，第二次才看清：
明度全都挤在 4%~9%，**画面里没有中间调**。

抬亮的方式很重要：

| 做法 | 结果 |
|---|---|
| 整体加白 | 暖红洗成脏粉，失去"夜" |
| 抬基底中段 + 收窄光斑 | 有光源、有暗部，层次出来 |
| 只提光池强度 | 一片橙雾，亮但浑 |

最后用的是第二种 + 第三种各一点：基底 `#2E1C17 → #3A2C26`（生辰期
`#4A3025`），同时把顶光从 `68%×44%` 收到 `54%×38%`、光池从 `46%×34%`
收到 `38%×28%`。**范围不收窄，提亮就只是变浑。**

粒子贴图的峰值也从 0.62 抬到 0.70。0.78 试过 —— 字直接糊掉：
笔画的横竖之间被加法混合填满，一个字涨成一条发光的横条。
0.62 发闷、0.78 糊死，0.70 在这两个失败之间。

### 19.5 四个坑（都会静默失败）

**① `display: none` 的节点量不出尺寸。**
`play()` 里先 `root.style.display = 'block'` 再 `resize()`。反过来的话
`clientWidth` 是 0，画布变成 0×0 —— 不报错，也什么都不显示，只是黑屏。

**② `canvas.width = ...` 会重置 context。**
`getContext` 之后再去设宽高，之前建好的 `createRadialGradient` 就废了，
画出来是一张透明的空图。先定尺寸，再取 context。

**③ 每帧写 CSS 变量会掉 20 帧。**
`document.body.style.setProperty('--mood-city', ...)` 每帧一次，浏览器
每帧要重新算样式，而 body 的背景是 10 层渐变叠一张 SVG 天际线。
61fps → 38fps。变化小于 0.8% 就不写，开销归零。

**④ `frames` 是 `window.frames`。**
不是这次引入的，但同年早些时候踩过：那个全局变量名撞了浏览器内置属性。
新模块里一律用局部变量。

### 19.6 节奏与跳过

三十秒不能跳过，第二次打开的人会烦 —— 而这一站会被反复打开
（信、往年、三连都在后面）。**点一下画面即跳过。**

跳过时先把开场层 `display: none` 再交棒。留一屏冻结的光点在后面当背景，
"跳过"看起来会像"卡住了"。

交棒也不等淡完：`root.classList.add('opening--out')` 之后**立刻** init 粒子字，
两者重叠 0.8 秒。原来的顺序是"等 700ms 淡完再 init"，中间留一段纯黑，
观众看到的是"光核没了 → 等一下 → 数字跳出来"。

烟花同理：开场这三十秒天上不能同时炸礼花，两种情绪会互相抵消。
`startFireworks()` 从页面加载时挪到了开场结束之后。

### 19.7 每年它会自己变

不需要重做这段动画。往 `data/history.js` 的 `points` 里加一条带日期和
人数的采样点，开场会自动变长、变亮、多一段字幕。

这是这一版和之前最大的区别：**以前每年要换文案，现在每年多走一段路。**

## 20. 密一点的粒子，一次说完的话（2026-11-12 夜）

用户看完开场之后给了三条，都是"减法"：

> 要去掉（倒计时），让光核直接接「祝」。「生日快乐」四个字改成更密的粒子。
> 还有后面，名字和头像，不需要再重复出现一次。

### 20.1 删掉 3、2、1

原来的顺序是：开场 → 倒数 3、2、1 → 「祝」→ 名字 → 「生日快乐」……

问题不在倒计时本身，在于**它和前面的开场是两套语法**。开场刚用三十秒
讲完她三年的增长，接着数三个数——读起来像视频重新加载了一遍。

`countdown: 0` 即可，`buildSequence` 里的判断本来就是 `> 0` 才插入。
四个年份文件（含 `_template.js`）一起改，以后新增的年份也不会带回来。

**同时删掉了前导空帧。** `buildSequence` 原来以 `''` 开头，作用是
"让画面先从空白开始"。现在交棒那一刻画面里已经是一个收拢的光核，
再空 1.2 秒，看到的是"光核停住、卡了一下"。去掉之后第一帧就是「祝」，
光核直接散成字。

`CONFIG.timeline()` 里对应那行 `t += base * 0.6` 也要一起去掉，
否则弹幕淡出、长信浮出的时机整体晚 1.2 秒。

#### 20.1.1 第二次：不是调成 0，是把开关拆了

当天深夜用户回了一句：

> 3、2、1 倒计时还在，去掉。

查了运行时的值：`CONFIG.countdown === 0`，`buildSequence()` 拼出来的
第一帧就是「祝」——代码是对的，他看到的还是旧画面。

这暴露了一个设计问题：**我们把"关掉"实现成了一个可以被数据推翻的默认值。**
`countdown` 有两条进入路径（`data/YYYY.js` 注入 + `CONFIG` 默认值 3），
只要浏览器缓存了其中任何一份旧文件，倒数就会回来，而且改代码的人
看着源码会以为已经删干净了。

所以这一版把它连根拔掉：

| 位置 | 处理 |
|---|---|
| `js/config.js` `CONFIG` | 删掉 `countdown: 3` 默认值 |
| `js/config.js` `buildSequence` | 删掉插入 `#countdown N` 的分支，参数 `withCountdown` 一起去掉 |
| `js/config.js` `timeline` | 删掉 `t += countdown * perCount` 与 `perCount` 变量 |
| `js/index.js` | `buildSequence(true)` → `buildSequence()` |
| `index.html` | 不再 `if (y.countdown != null) CONFIG.countdown = y.countdown` |
| `data/2024·2025·2026·_template.js` | 删掉 `countdown` 字段本身 |

引擎里处理 `#countdown` 的那段（`js/index.js` 的 `case 'countdown'`）留着 ——
它是通用能力，手动拼 `'#countdown 3'` 还能用，只是没有任何代码会自动拼它了。

### 20.2 名字和头像，只出现一次

序列原来是：

```
祝 | 辣椒素素素 | 生日快乐 | 一百万人 | 好幸福 | 头像 | 昵称 | 头像 | ♥
```

名字出现两次（第二帧 + 高潮段中间），头像出现两次。而名字在
「祝 / 辣椒素素素 / 生日快乐」里已经念过一遍了——再夹在两张头像中间，
等于同一个人被介绍两次。

现在：

```
祝 | 辣椒素素素 | 生日快乐 | 一百万人 | 好幸福 | 头像 | ♥
```

念名字 → 看脸，一次说完。`timeline()` 里那段从 `hold * 2 + accent`
改成 `hold`，`accentHold` 这个配置项保留但不再被读取。

> `#accent` 这个动作本身没删——它是"用头像配色显示文字"，以后想在
> 别处插一句同色系的话还能用。

### 20.3 密度：9/6 → 6/5

| | 改前 | 改后 |
|---|---|---|
| `GRID_GAP` 桌面 / 手机 | 9 / 6 | **6 / 5** |
| 「生日快乐」粒子数 | ~1630 | **3667** |
| 帧率（1440×900，演出中） | 61 | 40（优化后 **52**） |

道理上一节已经写过：9 的间距下横竖之间要靠光晕"糊"才连得上，放大看是一层
点阵；6 之后笔画自己站得住。

**但密度翻倍直接把帧率砸了 20 帧**，因为每帧要画 3667 次带重采样的
`drawImage`（64px 纹理缩到 4~7px）。解决办法不是降密度，是把缩小这一步
提前算好：

```js
// 按「颜色 + 最终直径」缓存成品贴图，运行时只是一次无缩放贴图
context.drawImage(spriteFor(c, d), (p.x - px / 2) | 0, (p.y - px / 2) | 0);
```

直径量化到整数像素之后只有七八种，缓存条目是有限的（颜色量化 × 七八个尺寸）。
坐标也必须取整——亚像素落点会让浏览器退回重采样路径，预缩放就白做了。
61 → 40 的代价收回到 52。

### 20.4 头像要反过来：单独疏一档

密度一高，头像立刻糊了。

文字是"一笔一画"，越密越实；头像只有**一圈轮廓线**，采样一密，相邻粒子的
光晕互相叠加，轮廓被填成一块云——看得见"有个东西"，看不出是什么。

所以采样步长拆成两个：文字用 `GRID_GAP`，头像用 `GRID_GAP * 1.5`
（桌面 9 / 手机 8），回到密度提升之前的观感。

实现上 `processCanvas(sampler, step)` 多了第二个参数。顺手把那个单循环
改成了按行双层循环：

```js
// 原实现用 p += step * 4 * width 跨行，前提是画布宽度必须是步长的整数倍。
// 头像步长和画布网格不一致时，跨行会累积漂移，采样点排成斜线。
for (y = 0; y < H; y += step)
  for (x = 0; x < W; x += step) { ... }
```

> 这一条值得记住：**同一个密度参数不能同时服务"字"和"图"**。
> 字的密度是为了让笔画闭合，图的密度是为了让轮廓透气，两者需求相反。

### 20.5 连带修掉的三件事

密度提高之后，原本看不出来的问题都被放大了。

**① 切换形状时多出来的粒子铺满全屏。**

`switchShape` 在目标粒子数少于现有粒子数时，会把多出来的粒子甩到画面随机
位置、透明度留 `0.3`，当作"星尘"。文字与头像的粒子数以前差得不远，
这层星尘像浮尘；现在文字 3667 颗、头像八百颗，两千八百颗星尘铺满全屏，
头像像浸在雪里，而且每帧都要各画一次——头像段帧率只有 33。

改成直接截断（`dots.length = d`）。少掉的粒子本来就该消失，不需要
"飞走"这个动作。头像段回到 59fps。

**② 弹幕在头像刚成形时涌回来。**

`runShow` 用 `timeline().portraitEnd` 排 `fadeIn`，而时间轴算的是**指令下发**
的时刻。粒子从头像外围飞拢、聚成一张脸要一秒多，等脸成形时弹幕正好回来，
压在上面。

排期挪到 `onPortraitReveal` —— 那才是"头像真的出现了"的时刻。
`runShow` 里留一个 `portraitEnd + 6000` 的兜底，防止图片加载失败时
弹幕再也不回来。

**③ 头像停留 5 秒不够它成形。**

删掉第二次头像和中间的昵称之后，头像总露出时间从 12 秒掉到 5 秒，
而 converge 的过渡要两秒上下——一半时间看到的是散点。
`portraitHold` 改 8500。**不要用"删掉一个就少一半"的方式估算时长，
要按"成形需要多久 + 看清楚需要多久"算。**

### 20.6 一条通用规则：字用密，图用疏

| 内容 | 采样步长 | 为什么 |
|---|---|---|
| 粒子文字（祝福语、名字） | `GRID_GAP`（6 / 5） | 笔画要闭合，密一点才连成光 |
| 头像 | `GRID_GAP × 1.5`（9 / 8） | 只有一圈轮廓线，密了会被光晕填成一团云 |
| 图标（爱心） | `GRID_GAP × 1.5`（9 / 8） | 同上，实心图形用密采样会变成一团绒毛 |

实现在 `processCanvas(sampler, step)` 的第二个参数。三处调用分别传
默认值 / `gap * 1.5` / `gap * 1.5`。

如果以后加了新的"图形帧"（照片、插画），照这个表走，别用文字的密度。

## 21. 让三十秒有重音（2026-11-12 深夜）

用户看完开场：

> 开头还可以但是缺了点感觉，还有点击跳过太容易错过了，
> 要不双击跳过或者其他方案。

「缺了点感觉」是个很具体的诊断，只是他自己没拆开：**这一段没有节拍。**

### 21.1 问题：均匀地变多，等于没有发生任何事

原来的三十秒里，唯一的变量是「光点的数量」。数量按真实曲线增长，
所以它确实在变——但人眼读到的是一条**进度条**：多一点、再多一点、
满了、收起来。

数字在长，可是没有一个时刻是"到了"。而真实的一年不是这样的：
破万、破十万、破百万，每一次都是一个下午被人截图发出去的时刻。

**所以缺的不是更多特效，是重音。**

### 21.2 加了四个节拍

| 时刻 | 做什么 | 为什么 |
|---|---|---|
| 0s | 第一颗光点从 12% 亮到满（0.9s），尺寸 58→120 | 原来是第一帧就全亮，读起来像屏保；点亮的动作才像"有人伸手开了灯" |
| 每个采样点 | 全屏亮度 ×1.55、颗粒 ×1.14、荡开两圈光环（1.5s） | 人群一起吸一口气。"到了"需要一个身体反应，不是一行新数字 |
| 28.2s 后 | 光核跳两下（720ms 一次，指数衰减） | 不加是"光被吸进一个洞"；加了是"它攒起来了，而且它是活的" |
| 27s 起 | 最后一句换成宋体、18px | 前面几行是刻度（等宽、克制），最后一句是落款（衬线、有重量）|

最后一条是最省的：**同一句话，换一个字体家族，就从"数据"变成"话"。**
mono 排中文每个字占一个等宽格，字与字之间是散的，像表格；
宋体连起来才有"写完一句话"的停顿。

### 21.3 顺带修掉的两个过曝

改节拍的时候把收拢段拍清楚了，发现光核是一块**纯白的棉花**：

- 落点在 `pow(rand, 1.15) * 168`，大部分点挤在半径 100 以内
- 收拢时颗粒放大到 27 倍（`16 + lift * 11`）

980 颗在 lighter 下叠加，中心必然饱和。改成：

| | 改前 | 改后 |
|---|---|---|
| 落点分布 | `pow(rand, 1.15) * 168` | `pow(rand, 0.75) * 200` |
| 收拢时颗粒 | `16 + lift * 11` | `16 + lift * 4` |
| 收拢时亮度 | 不变 | `× (1 - lift * 0.30)` |
| 纵向压扁 | `or * 0.62` | `or * 0.88` |

0.62 那版是一朵横向的云，像雾；0.88 才是一团。

### 21.4 跳过：从单击改成双击

**问题不是"跳过难找"，是"太容易被误触"。** 这一层铺满全屏（z-index 3），
而开场三十秒里观众最常做的动作恰恰不是跳过，是**把音乐打开**——
手指落在右上角，那一下同时也算跳过。三年攒下来的开场在第二秒就没了，
人还以为是自己点错了。

现在的规则：

1. 点击落在 `button / a / .fab / .social / .triple` 上 → 完全忽略（那是在操作界面）
2. 第一下 → 右下角浮出「再点一下跳过」，2.6 秒后自己消失
3. 两下之间 < 480ms → 真的跳过

提示**只在点过一次之后才出现**。没点的时候不出现，是因为开场是一次性的仪式，
任何常驻提示都是打扰；点了才出现，等于把"还有第二下"告诉正在动手的人。

跳过也不再是 `display: none` 硬切：画布继续跑，用 0.64 秒把整体亮度退到 0。
光点还在飞、城市还在亮，只是"这一段结束了"。原来的硬切看起来像播放器被按坏。

> 提示的位置从"底部居中"挪到"右下角"：底部居中那一带是
> 「点击右上角的按钮可以开启音乐」那条 toast 的地盘，两个东西会叠在一起。

## 22. 开场只属于生日；字要一个个落下来（2026-11-12 深夜）

用户三句话：

> 平时版应该不需要开头吧。
> 头像成形时那 7 发烟花盖脸，减到 2~3 发挪两侧，要改。
> 生日版开头的文字，应该一个一个出现然后排列出来，这样更有感觉吧。

### 22.1 三十秒是仪式，不是门票

开场是一次性的仪式：一年只此一次，所以值得等。但平时进来的人是**路过**——
想看日子、想翻相册、想确认还有多少天。给他一段必须等三十秒的演出，
等于在门口挂了一把锁。

`start()` 里现在只在这一个条件下播开场：

```js
var festive = document.body.classList.contains('mode--festive');
if (festive && window.Opening && ...) Opening.play(beginShow);
else beginShow();
```

安静期直接交棒。开场那个"光核收拢"本身是贺词的一部分，删掉之后
安静期的演出从头到尾是同一套语气，没有被硬插一段热闹。

### 22.2 一句话，拆成一个个字

原来整行文案用一条 `opacity + translateY` 的动画淡入 —— 读起来是
"一张字幕被切上来"。现在每个字是一个 `<span class="ol-ch">`，
各自从下方 10px、散焦 6px 处落到自己的格子里：

| | 数字行 | 落款 |
|---|---|---|
| 字间隔 | 62ms | 118ms |
| 单字时长 | 0.95s | 1.15s |

62ms 是"念数字"的节奏，118ms 是"说一句话"的节奏。同一套动画，
只改两个数，语速就变了。

**宽度必须先占住。** 一个字一个 `inline-block`，在动画开始前就把位置排好；
如果是"打到哪算哪"，后面的字会被一个个挤着往右跑，看起来像排版事故，
而不是排列。

**父层只负责退场。** 父层的动画变成 `openingLabelFade`（前 58% 全亮，
之后淡出）。要是父层还管出现，整行会在第三个字亮起来的时候开始变暗。

坑：`span` 里的普通空格在 `inline-block` 下会被折叠，
「2026-11 · 138.6 万人」会挤成「2026-11·138.6万人」。空格一律换成 `nbsp`。

### 22.3 烟花：七发绕圈 → 两三发侧幕

原来的写法是一圈七发绕着画面中心炸。出发点是"把视线托起来"，
实际是礼花正好开在那张刚聚好的脸上 —— 整段演出最该看清的一帧，
被自己放的烟花糊掉了。

现在：手机两发、桌面三发，只落在脸的两侧，第三发更高也更靠外。
左右故意不对称，对称的两发像一对耳环。

#### 排查中发现的三个真问题

**① 相机朝向把整片天关掉了。** `yaw` 的基准值一直是 `π`，
而 `rasterizePoint` 的可见性判据是 `1/z ∈ (0,1)`，也就是变换后 z 必须 > 1。
`yaw = π` 把每个点绕到相机背后（z 变负），于是**所有烟花都被判成看不见**：
不报错、不闪烁，就是一片空天。实测 152 颗火花里 0 颗通过可见性检查。
改成绕 0 呼吸之后，152/152 全部可见。

**② 位置算错了三成。** 反向解投影写的是 `x = dx / scale * z`，
但投影实际除的是 `z - playerZ`（相机在 -25），
所以所有落点都往中间缩了 0.63 倍 —— 写着"两侧"，炸出来贴着两颊。

**③ 小礼花会瞬间死亡。** 火花的存活判据是 `radius > 5`（绝对半径）。
想让礼花小一点，半径先被这条阈值判死：设成 0.2 倍时一朵都看不见。
改成 `radius > r0 * 0.16`（按出生大小的比例），
"变小"才不再等于"变短命"。

#### 尺寸靠倍率，不靠挪远

给 `splode()` 加了第四个参数 `{ size, spread, count }`，都是倍率。
挪远也能让小，但挪远之后火花变成一串细线，像流星雨不像礼花。
现在是原尺寸的六成：一朵约 240px 宽，落在两侧，
脸仍然是画面上最大最亮的东西。

#### 头顶按住两秒

头像成形时把随机巡回礼花停掉（`__seedHoldUntil = frames + 170`），
在飞的种子也清空。这两秒里天上只有刻意放的那两三发 ——
随机的礼花十有八九会开在脸上。

## 23. 字落完就留在那儿（2026-11-13 凌晨）

用户看完逐字落位：

> 我的意思是开头文字一个一个都显示出来，但是不需要消失，这样不是更好吗？

### 23.1 一行字不是字幕，是刻度

原来那一行挂着一个 3.9 秒的淡出：字刚落齐，整行就开始退。理由是"两句之间要留空"。

但采样点是按**真实日期**排的：2024 年那九个月只涨到 14 万，两行之间隔着十几秒。
于是观众看到的是——

```
写完一行 → 擦掉 → 空着 → 再写一行
```

屏幕在闪，而不是"这条线一直在往前走"。

现在字落完之后**不擦**。它就一直挂在画面上，直到下一个刻度把它顶掉。
换的那一下也不是硬切：旧行先退 0.18 秒，新的再落位。
直接清空重建是"啪"一下闪掉，像电视换台；有那 0.18 秒才是"这一行翻篇了"。

### 23.2 落位从 CSS animation 改成 JS 推

原来每个字一条 `animation: openingCharIn`，靠 `--i × 62ms` 的 delay 错开。
这个写法有两个代价：

1. **每个字一条动画，也就是每个字一个合成层**。十几个字同时落位，
   手机上是白付的钱；而且每条动画的进度都由合成器单独持有，
   出了偏差只能靠逐帧比对像素来查。
2. **状态不在手里**。"还剩几个字没落完""这一行到底落齐没有"
   都要回头去问 `getComputedStyle`，而它给的答案和那一帧画出来的东西
   并不总是同一件事（见 23.3）。

现在 `paintChars` 只负责把字排好并记下起始时刻，`tickChars` 在每帧里
按 `(now - start - i × stagger) / dur` 推每个字的 `opacity` 和
`translateY(12px → 0)`，落齐之后把终态写死、`charLive = false` 停手。
最多十几个字、持续 1.8 秒，之后就完全不碰 DOM。

| | 数字行 | 落款 |
|---|---|---|
| 字间隔 | 62ms | 118ms |
| 单字时长 | 0.95s | 1.15s |

`easeOutCubic` 走完；60% 处直接给 `opacity: 1`，
剩下 40% 只做位移 —— 字是"落到位置上"，不是"边落边亮"。

同时把 `filter: blur(6px)` 的散焦去掉了：11px 的字配 6px 模糊，
落下来之前那几个字等于完全看不见，读起来是"缺字"而不是"虚化"。

### 23.3 一个把我坑了很久的假问题

改完第一次截图，画面里每行只有前七个字，后面空着——
看起来像是"逐字落位在字多的时候会卡住"。我顺着这个假设改了两轮
（去 filter、去 transform、把整行移到 body 上去），全都无效。

真相是坐标：`shot.mjs` 的窗口是 1080 宽，而页面 `innerWidth` 报 1418
（两边差一个缩放系数），**`--clip` 吃的是视觉坐标**。
我按 CSS 坐标裁 520~1000，实际裁到的是画面中间那一刀，
正好切在第七个字后面。按视觉坐标重裁之后，`- 01 · 14 万人` 一个不少。

那两轮改动里唯一值得留下的是"去 filter"——它对 11px 的字本来就是负收益。
剩下的是教训：**截图对不上时，先怀疑自己给的坐标，再怀疑渲染引擎。**

### 23.4 后记：换句这件事，第二天上午就去掉了

这一节写的是"落完不擦、旧行先退 0.18 秒再换新的"。用户看完之后把意思
补全了 —— 他要的不是"一行一直挂在屏幕上"，是**所有行同时在**。
于是换句（`paint()` 与 `.opening-label--swap`）整条路径都删了，
改成往上摞成阶梯，见下一节。

留下的结论只有一条是对的：**别让数字自己淡出。** 采样点之间隔着十几秒，
中间空着会读成"屏幕在闪"。换成阶梯之后，这条变成"走过的行退到六成亮，
但不擦"。

## 24. 一行一行摞成阶梯（2026-11-13 上午）

用户看完"字落完就留着"，把意思说全了：

> 我的意思是，粉丝数开头，一个一个显示然后像一个阶梯一样，能看到所有，
> 这样不是更好吗。

### 24.1 换句是在逼人记住上一句

上一版是**换句**：一行挂在那儿，下一个采样点来了就把它顶掉。
观感上比"擦掉再写"好，但逻辑没变 —— 画面上永远只有一行数字。

于是"1000 → 138 万"这个落差，得靠观众自己记住上一行才成立。
而这三年真正的意思不是"现在有一百三十八万人"，是**每一级的差**：
1000、14 万、40 万、100 万、138 万，摆在一起才看见"越走越快"。

现在：**不换句，往上摞。** 每一级落下来就在那儿，一行一列排到画面底部，
走过的行退到六成亮但不擦。十一级同时挂着，落差是撞进眼睛里的。

这也和画面左边那件事说同一句话：光点一颗一颗升起来（人数在长），
数字一级一级往下摞（人数长到了多少）。两边是同一条曲线的两种画法。

### 24.2 排布：一步 13px，整列先让半格

```
2024-04 · 1000 人
  2025-01 · 14 万人
    2025-03 · 23 万人            ← 每一级往右挪一步
      ...
        2026-11 · 138.7 万人      ← 最新的一级永远在最下面
          一百三十八万人，今晚都在  ← 落款不参与错位，居中
```

- `STAIR = 13px` 一步，窄屏按 `W * 0.03` 收（390 宽时约 11.7px）。
  不收的话，11 级的错位加一行字就是一条从左边缘斜到右边缘的线。
- 整列先把**总错位的一半**让出来（`stairBase()`），重心才落在屏幕中线上；
  再按屏宽的 30% 兜一次底，免得窄屏上贴着左边。
- 采样点是数据里长出来的（今天 11 个，明年更多），所以这些数都不写死。

**为什么不用 transform 做错位**：`transform` 会让每个字各自进合成层，
而落字那一帧的 `translateY` 也用 `transform` —— 两套位移撞在一起，
落位会抖。用 `padding-left` 就没有这个问题。

### 24.3 整列的高度要一次占满

这是这一版最容易漏的一件事。

阶梯是从下面往上**顶**着长的（容器 `bottom` 锚定）：每加一级，
上面所有行都被顶上去一格。2025 年那一段采样点密到两秒一级，
于是整列一直在往上爬 —— **读者正在读的那一行会自己跑掉**。

现在第一级落下时就把整列的高度算出来写进 `min-height`
（`layoutStairs()`）：`采样点数 × 行高 + 落款高`。
之后每加一级只是往下填一格，已经落好的字一动不动，
底下那段空白就是"还没走到的那几级"。

行高用 `getBoundingClientRect().height` 现量，不写死 —— 字号在三个
断点里变过（11px / 10px / 15px），写死一个数迟早对不上。

### 24.4 什么时候算"到了"：从"离谁近"改成"走到没到"

`markAt()` 原来取**最近**的采样点。那是给"换句"设计的：
画面上只有一行，显示离此刻最近的那个数。

摞成阶梯之后，最近邻会把最前面那一级压成"前后各一半"——
2024-04 到 2025-01 隔着九个月，那一级只挂一秒多，字都没落齐就被顶掉。

改成 `reachedIdx()`：走到就是走到。光点满到一千人，才写"1000 人"。
第一级因此能安安静静挂四分半钟 —— 那九个月本来就该这么慢。

顺手把全屏的那一下"吸一口气"也接到同一个函数上（`syncPulse`）：
数字出现和光满上来是同一瞬间，不是两件事。

### 24.5 两条小修

**同一个月的两条要退到完整日期。** 数据里有 2025-12-11 的 60 万和
2025-12-21 的 64 万，都写成「2025-12 ·」的话，一列里出现两个一模一样的
日期，看起来像数据错了。撞月就写全日期（`markLabel()`）——
多五个字，换来"那十天涨了四万"这个事实。

**暗晕要跟着笔画走。** 原来那层暗影是 `0 1px` 的投影，一行字的时候够用；
十一级泡在星光里，穿过字形中心的光点它压不住，一排数字会缺几个笔画。
换成 `0 0 4px` + `0 0 12px` 的零偏移暗晕，星点只能在字的四周亮。
**顺序很重要**：CSS 的多重 `text-shadow` 是先写的盖在上面，
暗晕必须写在暖光前面，写在后面会把暖光压掉，字看着发灰。

### 24.6 时间轴跟着挪

最后一级（现在的人数）原来只挂两秒就被收拢压住，而"看全这一列"
正是这段戏要给的东西。所以：

| | 原来 | 现在 |
|---|---|---|
| 生长结束 `T_GROW` | 22000 | 21000 |
| 收拢开始 `T_LIFT` | 24000 | 26000 |
| 收拢到最紧 | 28200 | 30200 |
| 交棒 `T_END` | 29800 | 31800 |

整列完整地停 5 秒，再交给光。开场从 29.8 秒变成 31.8 秒 ——
为这口气多两秒，值。收拢那几秒里，最上面两三行会落进光核的亮部，
那时它们已经是六成亮的老行，读起来是"最早的那几级化进光里"，
不是被糊掉。

### 24.7 顺手把截图工具的坐标系钉死了

上一节（23.3）那个"每行只画前七个字"的假问题，根子是
`shot.mjs` 的窗口宽 1080、页面 `innerWidth` 报 1418，`--clip` 吃视觉坐标。

现在 `Page.enable` 之后直接 `Emulation.setDeviceMetricsOverride`
把视口钉成 `--size` 给的尺寸、`deviceScaleFactor: 1`。
截图和 clip 从此逐像素一致 —— 这一版的每一次核对都靠它，
不用再猜坐标。
